# A Star Schema for Sales

The shop's database (`fixture/01_shop.sql`) is built for taking orders: `customers`,
`products`, `orders` and `order_items`, normalised. Analysts want to slice revenue by month,
category, country and quarter without knowing that schema. Build them a **star schema** in
`star.sql`, then answer two questions **from the star only**.

## `star.sql`

Create these four tables and fill them from the OLTP tables:

```text
dim_date     (date_key, full_date, year, quarter, month, day_of_week)
dim_customer (customer_key, customer_id, name, city, country)
dim_product  (product_key, product_id, name, category)
fact_sales   (order_id, line_no, date_key, customer_key, product_key,
              quantity, unit_price, revenue)
```

| Table | Rules |
| --- | --- |
| `dim_date` | one row for **every day** from the first to the last order date (also days without orders); `date_key` is the date as the number `YYYYMMDD` and the primary key; `day_of_week` is ISO (1 = Monday, 7 = Sunday) |
| `dim_customer`, `dim_product` | one row per source row, also customers who never ordered; the primary key is a **surrogate key** generated by the database (an identity column); the source id (`customer_id`, `product_id`) is the **natural key** and unique |
| `fact_sales` | the **grain** is one row per order line of an order that was **not cancelled**; `(order_id, line_no)` is the primary key; the three keys are foreign keys to the dimensions; `revenue` is `quantity * unit_price` (the price actually paid, not the list price) |

Order dates are the date of `ordered_at` in **UTC** (`ordered_at AT TIME ZONE 'UTC'`).

> [!TIP]
> `generate_series(first_day, last_day, interval '1 day')` produces the calendar, and
> `to_char(day, 'YYYYMMDD')::integer` and `extract(isodow FROM day)` describe each day.

## The reports

| File | Columns | Order |
| --- | --- | --- |
| `revenue_by_month_category.sql` | year, month, category, revenue | year, month, category |
| `revenue_by_country_quarter.sql` | country, year, quarter, number of orders, revenue | country, year, quarter |

The tests run `star.sql` and then **empty the OLTP tables** before your report runs, so a
report that still reads `orders` returns nothing. An order with two lines counts as one order.

Try your SQL with `docker run -it --rm --network none -v "${PWD}:/work" dojo-sql play`, which
loads the fixture, then `\i star.sql`.

There are 17 tests: 1 in `tests/visible.sql` and 16 hidden ones.
