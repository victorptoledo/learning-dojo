Besides the seats, each show sells standing places, up to `shows.standing_capacity`. Write
`standing.sql`:

| Column of `standing_tickets` | Rule |
|---|---|
| `id` | `bigint` generated by the database, primary key |
| `show_id` | required, references `shows` |
| `customer_id` | required, references `customers` |
| `quantity` | integer, required, more than 0 |
| `bought_at` | `timestamptz`, required, default `now()` |

- `standing_left(p_show integer) RETURNS integer`: the show's capacity minus the places
  sold.
- `buy_standing(p_show integer, p_customer integer, p_quantity integer) RETURNS bigint`:
  sells `p_quantity` places and returns the ticket's id, or returns `NULL` (and sells
  nothing) when fewer than `p_quantity` places are left. A quantity of 0 or less is an error
  (a check violation).

**The races** (show 2 has 3 places):

- Session A buys 2 places and its transaction stays open; session B tries to buy 2. B
  **waits**; if A commits, B returns `NULL`; if A rolls back, B gets its 2 places.
- A buys 1 and B buys 2: both sell once A commits.
- Sales of two different shows never wait for each other.
- At no moment does a show sell more than its capacity.

> [!TIP]
> This time no constraint can say "the sum of the quantities is at most the capacity", and
> counting the tickets before inserting has the same gap as in stage 1: two sessions count
> before either inserts. Make every sale of a show take its turn: which **row** do all of them
> share, and what does `SELECT ... FOR UPDATE` do to the second session that asks for it?
