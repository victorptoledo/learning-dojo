Write `schema.sql`: four tables, in an order that lets each foreign key point at a table that
already exists.

| Table | Column | Rule |
|---|---|---|
| `teams` | `id` | integer generated by the database, primary key |
| | `name` | text, required, unique |
| | `city` | text, required |
| `players` | `id` | integer generated by the database, primary key |
| | `team_id` | required, references `teams` |
| | `name` | text, required; unique within a team |
| | `shirt_number` | integer, required, from 1 to 99; unique within a team |
| `matches` | `id` | integer generated by the database, primary key |
| | `round` | integer, required, at least 1 |
| | `played_on` | `date`, required (the day it is, or was, scheduled) |
| | `home_team_id`, `away_team_id` | required, reference `teams`, never the same team |
| | `home_goals`, `away_goals` | integers, never negative; **both** `NULL` while the match is not played, both set once it is |
| `goals` | `id` | integer generated by the database, primary key |
| | `match_id` | required, references `matches`; deleting a match deletes its goals |
| | `player_id` | required, references `players` |
| | `minute` | integer, required, from 1 to 120 |
| | `own_goal` | boolean, required, `false` unless said otherwise |

Each club hosts each other club once: the same `(home_team_id, away_team_id)` pair can appear
only once (the reverse pair is the other match). A team that still has players cannot be
deleted.

Put every rule in the database (`PRIMARY KEY`, `REFERENCES`, `NOT NULL`, `UNIQUE`, `CHECK`,
`DEFAULT`): the tests write bad rows and expect PostgreSQL to refuse them, and the tests never
give an `id`, so `GENERATED ALWAYS AS IDENTITY` (or `BY DEFAULT`) must fill it.

> [!TIP]
> "Both `NULL` or both set" is one `CHECK` over two columns. Remember that a `CHECK` whose
> expression is `NULL` passes.
