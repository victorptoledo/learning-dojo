Write `ledger.sql`.

**The tables**

| Table | Column | Rule |
|---|---|---|
| `journal` | `id` | `bigint` generated by the database, primary key |
| | `memo` | `text`, required |
| | `posted_at` | `timestamptz`, required, `now()` by default |
| `postings` | `id` | `bigint` generated by the database, primary key |
| | `journal_id` | required, references `journal` |
| | `account_id` | required, references `accounts` |
| | `amount` | `numeric(14,2)`, required, never `0`: negative takes money out of the account, positive puts it in |

**The rule of double entry.** Every journal entry has **at least two postings**, all of them
on accounts of **one currency**, and its amounts **add up to zero**. The database checks it,
whoever writes the rows, but only when the transaction **commits**: a program inserts the
entry, then its postings one by one, and in between the entry is not balanced yet. At
`COMMIT` an unbalanced entry (or one without postings) fails with `23514` and nothing of the
transaction stays. `SET CONSTRAINTS ALL IMMEDIATE` runs the same check on the spot.

**The functions**

- `post(p_memo text, p_postings jsonb) RETURNS bigint` writes one entry and returns its id.
  `p_postings` is an array such as `[{"account": 2, "amount": -25.00}, {"account": 3,
  "amount": 25.00}]`. An entry that breaks the rule fails right away, inside `post`, with
  `23514`.
- `balance(p_account bigint) RETURNS numeric`: the sum of the account's postings, `0` for an
  account without any.

> [!TIP]
> A check that must wait for the end of the transaction is a **constraint trigger**:
> `CREATE CONSTRAINT TRIGGER ... AFTER INSERT ON postings DEFERRABLE INITIALLY DEFERRED FOR
> EACH ROW EXECUTE FUNCTION ...`. Its function runs at `COMMIT` (or at `SET CONSTRAINTS ...
> IMMEDIATE`) once per inserted row, and an exception there aborts the commit. Raise it with
> `USING ERRCODE = 'check_violation'`. The same function can check a whole entry from any
> of its rows, and a second constraint trigger on `journal` catches an entry with no postings
> at all.
